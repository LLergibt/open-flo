# Данные календаря и дневника

Владелец может читать и менять свой календарь и дневник. Связанный партнёр получает доступ на чтение, включая симптомы, интенсивность, настроение, интимные события и заметки. Сервер определяет владельца по текущей активной паре. Медицинские маршруты не дают администратору установки доступа к чужим данным.

Записи хранятся в SQLite на сервере установки. Существующие права файлов (каталог 0700, новые файлы БД/ключей 0600) ограничивают доступ других локальных пользователей, но не являются шифрованием БД. Владелец сервера, root и человек с копией файла/резервной копии технически могут прочитать записи. Сквозное шифрование не реализовано. Для доступа с другого устройства требуется HTTPS.

Содержимое дневника не отправляется внешним AI-сервисам, аналитике или внешнему API. Рендеринг заметок — обычный текст; HTML из них не исполняется. Ответы API имеют no-store, веб не сохраняет записи в localStorage/IndexedDB/service worker. Работа офлайн и синхронизация между локальными копиями в эту версию не входят.

Разрыв пары прекращает новые чтения через эту связь. Клиент очищает календарные данные при ошибке доступа и обновляет их при возврате на страницу. Уже прочитанный экран, снимок или сохранённую вне приложения копию отозвать удалённо невозможно. Запрос, начатый до разрыва пары, может завершиться на согласованном снимке БД до разрыва; следующий запрос проверяет связь заново.

Удаление аккаунта каскадно удаляет его календарь, настройки и дневник из действующей БД. Это не очищает исторические резервные копии, WAL/свободные страницы и внешние копии. Автоматическая политика сроков хранения резервных копий пока не реализована; ею управляет владелец установки. Резервные копии следует защищать вместе с серверной БД и ключами; не включать их в Git или публичные артефакты.

Права просмотра действуют на весь дневник. Экспорт и администраторский просмотр медицинских записей за рамками этого этапа.
