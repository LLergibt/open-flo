# Развёртывание Open Flo по IP

Схема рассчитана на один Linux-сервер с Docker Engine и Docker Compose v2. Nginx обслуживает веб и проксирует API по внутренней сети Compose. В Интернет публикуются TCP 80 и 443. API и SQLite остаются внутри Compose. Дневник, аккаунты и ключ JWT находятся в томе `flo-data`.

## 1. Подготовить сервер

Нужен публичный маршрутизируемый IPv4 или IPv6, доступный извне. Желателен закреплённый адрес. При NAT перенаправьте TCP 80 и 443 на сервер. Порт 80 останется нужен для продления. Проверьте, что эти порты свободны и разрешены в сетевом экране сервера и у провайдера. Потребуются Python 3, Git и доступ к Docker. Для автоматического запуска используйте системный Docker и systemd.

Let’s Encrypt выдаёт доверенные IP-сертификаты сроком около шести дней. Certbot подтверждает адрес через HTTP-01. Для адреса локальной сети, CGNAT или частного VPN публичное подтверждение этим способом недоступно. Для закрытой сети используйте собственный доверенный УЦ или имя и подходящую схему проверки. [IP-сертификаты и Certbot](https://letsencrypt.org/2026/03/11/shorter-certs-certbot) · [HTTP-01](https://letsencrypt.org/docs/challenge-types/)

## 2. Развернуть стек и получить сертификат

На сервере клонируйте ветку в постоянный каталог, например `/opt/open-flo`. Используйте доверенную копию с ограниченным правом записи. Таймер будет выполнять скрипт из этого каталога от root. Плейсхолдеры PUBLIC_IP и EMAIL замените своим реальным адресом и контактной почтой.

```sh
git clone --branch feat/auth-and-pairing https://github.com/LLergibt/open-flo.git /opt/open-flo
cd /opt/open-flo
sudo ./scripts/ip-tls.sh init PUBLIC_IP EMAIL
sudo ./scripts/ip-tls.sh install-timer
```

Если репозиторий закрытый, клонируйте с доступной вам авторизацией или серверным deploy key. Для IPv6 передайте скрипту адрес без скобок. Он сам добавит скобки в веб-адрес.

`init` сохраняет адрес в игнорируемом `.env.ip-tls`, собирает сервисы и запускает HTTP для ACME. До выдачи сертификата остальные HTTP-запросы получают 404. После выдачи HTTPS начинает обслуживать приложение, а обычный HTTP перенаправляется на настроенный IP. Cookies используют флаг Secure. Порт 8080 остаётся внутри сети Docker.

Откройте `https://PUBLIC_IP/health`. При первом развёртывании создайте администратора командой ниже. Она интерактивно запросит пароль и не нужна, если база уже содержит администратора.

```sh
sudo docker compose --env-file .env.ip-tls -f compose.prod.yaml exec api \
  flo-api create-admin --username root --display-name root
```

Скрипт поддерживает как `docker compose`, так и `docker-compose`. В примерах можно заменить команду на доступный вариант.

## 3. Продление и контроль

Таймер проверяет сертификат каждые шесть часов с небольшой случайной задержкой. Certbot сам определяет время продления. После успешной проверки нужные PEM-файлы публикуются в отдельный том Nginx. Скрипт проверяет конфигурацию и отправляет Nginx команду перечитать сертификат. Том Certbot с ключами ACME остаётся доступен только контейнеру Certbot. Таймер не собирает новые версии приложения.

```sh
sudo ./scripts/ip-tls.sh dry-run
sudo systemctl list-timers open-flo-ip-tls.timer
sudo journalctl -u open-flo-ip-tls.service -n 100
```

`dry-run` обращается к тестовому центру Let’s Encrypt и требует доступности порта 80 снаружи. При сбое проверьте журнал и доступность challenge с публичной сети. Для ручного повтора запустите `sudo ./scripts/ip-tls.sh renew`. Из-за короткого срока действия контролируйте срок сертификата и ошибки таймера. На Linux без systemd запланируйте ту же команду через свой планировщик с интервалом до шести часов.

## 4. Данные, обновление и Android

Сделайте резервную копию SQLite и ключа JWT до обновления или переноса. Для согласованной копии используйте встроенную команду SQLite `.backup` либо остановите API перед копированием тома. Проверьте, что резервная копия восстанавливается. Копия содержит личные записи. Храните её с ограниченным доступом.

Production и локальный Compose в этой папке по умолчанию имеют одно имя проекта и используют один том `flo-data`. Production заменяет локальный HTTP-стек, если оба запускаются с одним именем. Нативный dev-сервер использует отдельную базу `.data/flo.db`. Чтобы сохранить эти данные, перенесите согласованную копию базы и ключа в серверный том до старта API с правами UID 10001. Чистый сервер начинает с пустой базы.

Для обновления заберите нужный коммит, сохраните резервную копию и выполните `docker compose --env-file .env.ip-tls -f compose.prod.yaml up -d --build`. Тома сохраняются при обычном `down`. Команда `down -v` удаляет данные и сертификаты, поэтому для обычного обслуживания её не используйте. При смене IP сертификат надо выпустить заново. Сохраните базу, остановите таймер, уберите старую конфигурацию и сертификат с именем `flo-ip` из Certbot и тома Nginx, затем выполните `init` с новым адресом.

Android на сервер не копируется. Соберите клиент с `-PAPI_BASE_URL=https://PUBLIC_IP`. Для IPv6 укажите URL в виде `https://[PUBLIC_IPV6]`. Debug APK с USB-адресом продолжает использовать локальный API, пока не установите серверную сборку.
