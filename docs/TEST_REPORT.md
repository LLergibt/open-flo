# Проверка минимального каркаса

Дата: 16 ноября 2026 года. Проверяющий: независимый агент tester.

Проверен сценарий получения демонстрационного текста из SQLite через API и устройство каркаса. Блокирующих дефектов в выполненных проверках не обнаружено. Исполнение Android на устройстве, установленная PWA на iPhone и сборка контейнеров этим отчётом не подтверждаются.

## Реальные проверки

| Проверка | Результат | Доказательство и границы |
|---|---|---|
| Запуск API с временным файлом SQLite | Пройдена | Бинарный файл запущен отдельным процессом на `127.0.0.1:18080`; `/health` вернул `{"status":"ok","database":"ok"}` |
| Начальный текст через HTTP | Пройдена | `/api/message` вернул `{"message":"Привет из SQLite","source":"sqlite"}` |
| Изменение текста непосредственно в SQLite | Пройдена | После SQL UPDATE следующий HTTP GET вернул изменённую строку; сервер не перезапускался |
| Сохранение после перезапуска | Пройдена | Процесс API остановлен и запущен с тем же временным файлом; изменённый текст сохранился |
| Отсутствующая строка | Пройдена | После DELETE строки `id=1` маршрут вернул HTTP 404 и `{"error":"demo_message_not_found"}`; подстановки начального текста нет |
| Кеширование и CORS | Пройдена для успешного GET | Ответ содержит `Cache-Control: no-store`; разрешающий `Access-Control-Allow-Origin` отсутствует |
| Конфликт занятого веб-порта | Пройдена | `scripts/dev.sh` запущен с отдельной временной БД и API-портом 18081 при уже занятом 5173; Vite сообщил ошибку, скрипт завершился кодом 1 и остановил свой API; существующий веб-сервер сохранился |
| Успешный запуск и остановка `dev.sh` | Пройдена | Веб запущен на 5173, API на 18081 с временной БД; запрос через веб-прокси вернул текст SQLite. После SIGTERM скрипт завершился кодом 143; оба порта освобождены |
| Ожидание готовности API перед Vite | Пройдена после исправления | `dev.sh` ожидает успешный `/health`; первый запрос к `/api/message` после открытия веб-порта вернул HTTP 200 и сообщение из SQLite. В логе повторной проверки `ECONNREFUSED` отсутствует |
| Ошибка запуска API | Пройдена | При `BIND_ADDR=not-a-socket` API вернул `AddrParseError(Socket)`, скрипт завершился ненулевым кодом, Vite не запущен; порты 5173 и 18081 свободны |
| Синтаксис shell-скриптов | Пройдена | `bash -n scripts/dev.sh scripts/check.sh scripts/android.sh` |
| Структура Compose | Пройдена | `docker-compose config --quiet`; Docker daemon для этой команды не требуется |

Для сетевых проверок понадобился разрешённый запуск вне файловой песочницы: обычный запуск API завершился `PermissionDenied` при привязке локального порта. Использованы только loopback-адреса и синтетические временные данные. После тестов собственные процессы остановлены, временные БД удалены.

## Проверка исходного кода

- API читает строку из SQLite при каждом запросе. Миграция встроена в бинарный файл и не заменяет изменённое сообщение при повторном старте. Запрос параметризован; ошибки HTTP не раскрывают SQL и путь к БД.
- Веб-страница выполняет fetch при открытии и повторной попытке, проверяет HTTP-статус и JSON, имеет загрузку, ошибку и ограничение ожидания. Сообщение выводится обычной текстовой вставкой Svelte; HTML из БД не исполняется.
- Vite проксирует `/api` и `/health` к серверу. Production-конфигурация Nginx сохраняет тот же путь к API. Браузерному клиенту не требуется разрешающий CORS.
- Android использует нативный Compose UI. `HttpURLConnection` работает на `Dispatchers.IO`, с таймаутами, запретом перенаправлений и ограничением размера ответа. Отмена coroutine не преобразуется в пользовательскую ошибку.
- В Android `src/main` запрещает cleartext HTTP. Разрешение HTTP находится в debug-конфигурации. Задача `preReleaseBuild` требует явно заданный HTTPS API URL; отсутствие URL и HTTP-адрес должны завершать release-подготовку ошибкой. Это статическая проверка: фактический исход Gradle-задачи указывается отдельно после сборки.
- Сервер по умолчанию слушает loopback. Compose публикует только веб-порт на `127.0.0.1`; файл SQLite сохраняется в именованном томе. В образе API предусмотрен непривилегированный пользователь.
- Веб не содержит изображений, CDN-шрифтов или кода генерации изображений. Манифест задаёт standalone-режим, service worker не добавлен; автономная работа приложения пока не реализована.

## Отдельные результаты разработчиков

Эти тесты включают чтение изменённого значения, повторное открытие БД, удалённую демонстрационную строку и ошибку закрытого пула в `/health`. Независимая проверка HTTP выше использует другой способ запуска — реальный серверный процесс и Python-клиент.

Координатор сообщил результаты реальной проверки в браузере: исходный текст отображается; изменение SQLite и нажатие кнопки показывают новое значение; остановка API вызывает HTTP 502 и состояние ошибки; запуск API и повторная попытка восстанавливают успешный экран. В проверенной браузерной консоли ошибок и предупреждений не обнаружено. Скриншот сохранён координатором в `outputs/web-skeleton.png` текущего чата. Эти наблюдения выполнены координатором, а не агентом tester.

Результаты сборки веба и Android координатор фиксирует в итогах задачи. Они не приравниваются к проверкам, выполненным этим агентом.

Координатор также сообщил успешный общий запуск `./scripts/check.sh`, включающий Rust-проверки, Svelte check и веб-сборку. Этот результат отделён от независимых HTTP- и lifecycle-проверок выше.

## Оставшиеся границы

- В первоначальной версии `dev.sh` Vite запускался раньше API, и ранние запросы получали `ECONNREFUSED`. Координатор добавил ожидание `/health`. Повторная проверка подтвердила устранение этого сценария: первый запрос после запуска Vite успешен. Проверена также остановка API при ошибке запуска. Внешние сбои после запуска по-прежнему обрабатываются интерфейсом повторной попытки.
- Docker daemon в окружении не запущен. Синтаксис Compose проверен; Dockerfiles рассмотрены статически. Контейнерные сборки, Linux-исполнение бинарного файла, права тома и контейнерная маршрутизация требуют проверки при доступном Docker daemon.
- Android-экран не запускался на эмуляторе или физическом устройстве этим агентом. Компиляция APK сама по себе не подтверждает HTTP-соединение в Android.
- Установка PWA на iPhone, автономность и системные уведомления в текущий каркас не входят и не проверены.
- Авторизация и партнёрские права пока не реализованы. Тестовый открытый API содержит только демонстрационный текст; выводы о безопасности медицинских данных делать рано.
- Алгоритм менструального цикла отсутствует на этом этапе и не проходил проверку.
