# Приглашения партнёров и собственный пароль

| Маршрут | Доступ и результат |
| --- | --- |
| POST /api/me/invite | Владелец дневника без пары. Ответ 201: token, url (или null), expires_at в ISO 8601. |
| DELETE /api/me/invite | Владелец отзывает незавершённое приглашение. Ответ 204. |
| POST /api/invites/preview | JSON: token. Ответ: tracker_display_name, expires_at. Просмотр не расходует приглашение. |
| POST /api/invites/register | JSON: token, username, display_name, password, client (web или native). Ответ 201: user, pair. |
| POST /api/me/invite/accept | Авторизованный партнёр. JSON: token. Ответ 201: Pair. |
| POST /api/me/password | Любая авторизованная роль. JSON: current_password, new_password. Ответ 204. |

## Жизненный цикл приглашения

Токен содержит 256 случайных бит, передаётся как 64 шестнадцатеричных символа. В БД хранится только хеш. Срок — 24 часа; новое приглашение отзывает предыдущее. Создание пары, включая действие администратора, отключение владельца или изменение его пароля удаляют незавершённое приглашение. После удаления пары старые ссылки не восстанавливаются.

Недоступное, истёкшее, использованное или отозванное приглашение возвращает 404 с error=invite_unavailable. Preview раскрывает только отображаемое имя владельца и срок. На создание, просмотр и регистрацию действуют ограничения частоты запросов.

Регистрация создаёт только роль partner. Аккаунт, пара и погашение приглашения записываются одной транзакцией. При ошибке новый аккаунт не сохраняется. После регистрации клиент выполняет обычный вход; регистрационный маршрут не создаёт сессию. Существующий партнёр явно подтверждает привязку после входа. GET, preview и login не создают пару.

## Ссылка и клиенты

PUBLIC_APP_URL задаёт точный HTTPS origin веб-приложения без пути; HTTP разрешён для loopback-разработки. Сервер формирует /#invite=TOKEN только из этой настройки, не из Host. Без настройки url=null: веб использует текущий origin, Android позволяет скопировать код.

Веб удаляет fragment из адресной строки до preview, хранит приглашение в памяти SPA и сохраняет его при выходе и повторном входе в пределах этой страницы. Перезагрузка очищенной страницы теряет приглашение; его можно открыть снова по исходной ссылке.

Android принимает код или ссылку вручную, извлекает токен и отправляет запросы только настроенному API. Адрес из приглашения не загружается нативным клиентом. Обычная ссылка открывает веб; Android App Links пока не настроены.

Пароли и токены не записываются в query, журнал приложения или localStorage. Все изменяющие запросы защищены проверкой Origin; веб использует HttpOnly cookies, Android — Bearer и refresh. Интерфейсы требуют явного подтверждения привязки.

## Собственный пароль и bootstrap

Текущий пароль проверяется Argon2; новый соответствует общему правилу 12–128 символов. Успех атомарно меняет хеш, отзывает все сессии аккаунта и незавершённые приглашения, очищает cookies. Клиент возвращается ко входу. Неверный текущий пароль возвращает 401 invalid_credentials; это не истечение сессии и не повод для refresh или logout.

Скрипт ./scripts/create-admin.sh без аргументов задаёт логин root и отображаемое имя root. Пароль вводится пользователем. Явные аргументы сохраняются; существующие аккаунты автоматически не переименовываются.

Проверки: Rust integration tests, веб-тесты и сборка, Android JVM tests, lint и сборка APK. Запуск на телефоне в этот этап не входит.

## Административные ссылки без пары

POST /api/admin/invites с JSON {role: tracker|partner} возвращает 201 с token, url, expires_at, role. DELETE /api/admin/invites/{role} отзывает ссылку текущего администратора для этой роли. Для каждой роли хранится одно незавершённое приглашение администратора; создание нового отзывает предыдущее для той же роли. Администраторская роль запрещена и проверкой API, и CHECK в БД.

Общие preview/register обрабатывают оба типа приглашений. Preview дополнительно возвращает kind (pair или account) и role. Для kind=account регистрация создаёт только аккаунт указанной сервером роли и возвращает pair=null; endpoint привязки существующего партнёра такую ссылку не принимает. Token потребляется атомарно. Отключение/удаление/смена пароля выдавшего администратора отзывает ссылки.
