# Open Flo

Open Flo развивается как open-source альтернатива Flo для самостоятельного размещения. Это трекер менструального цикла и личный дневник с отдельным доступом для партнёра. Аккаунты и записи хранятся на вашем сервере. Приложение доступно в браузере, в виде PWA на iPhone и как нативный клиент на Android.

## Возможности

- **Календарь цикла.** Отмечайте начало и конец месячных, исправляйте даты в истории и настраивайте длину цикла. Календарь отличает фактические даты от прогноза начала и длительности месячных, предполагаемой овуляции и фертильного окна.
- **Дневник дня.** Сохраняйте симптомы, боль, настроение, либидо, интимные отметки и заметки. Записи открываются по нажатию на день.
- **Доступ для партнёра.** Связанный партнёр видит календарь и записи владельца и ведёт свои отметки. На одном экране записи владельца выделены розовым, записи партнёра — синим. Каждый редактирует свои записи. Данные о цикле, кровотечении и выделениях вводит владелец.
- **Просмотр без сети.** PWA и Android сохраняют последнюю загруженную копию календаря и дневника. Сначала откройте календарь с подключением. Офлайн-копию можно просматривать до семи дней после загрузки. Для добавления и изменения записей нужно подключение.
- **Управление аккаунтами.** Администратор создаёт и связывает аккаунты, отключает их, сбрасывает пароли и выдаёт одноразовые ссылки регистрации. Владелец дневника может пригласить партнёра из профиля.

Прогноз рассчитывается по истории цикла и настройкам. Это календарная оценка, которую нельзя использовать как метод контрацепции. [Как устроен прогноз](docs/CYCLE_ALGORITHM.md)

## Развёртывание на своём сервере

Для готового сценария по IP нужен Linux с Docker Engine, Docker Compose, Git, Python 3 и systemd. У сервера должен быть публичный IP, доступный извне по TCP-портам **80** и **443**. Порт 80 используется для выпуска и продления сертификата, порт 443 — для приложения. Домен не обязателен.

### 1. Скачать проект и включить HTTPS

На сервере замените `ВАШ_ПУБЛИЧНЫЙ_IP` и `ВАША_ПОЧТА` на свои значения. Для IPv6 передайте `init` адрес без квадратных скобок, а в HTTPS-адресе укажите его в скобках.

```bash
sudo git clone --branch main https://github.com/LLergibt/open-flo.git /opt/open-flo
cd /opt/open-flo
sudo ./scripts/ip-tls.sh init ВАШ_ПУБЛИЧНЫЙ_IP ВАША_ПОЧТА
sudo ./scripts/ip-tls.sh install-timer
curl -gfsS 'https://ВАШ_ПУБЛИЧНЫЙ_IP/health'
```

`init` собирает контейнеры и получает сертификат Let’s Encrypt. `install-timer` включает автоматическую проверку и продление сертификата. Если `/health` отвечает `{"status":"ok","database":"ok"}`, API подключён к базе. [Подробности развёртывания, диагностики и продления](docs/DEPLOYMENT.md)

### 2. Создать первого администратора

Запустите скрипт из той же папки на сервере.

```bash
sudo ./scripts/create-admin.sh --docker
```

Скрипт создаёт администратора приложения с логином и отображаемым именем `root`. Задайте пароль длиной 12–128 символов в терминале. Ввод скрыт, стандартного пароля нет. Это учётная запись Open Flo. Если вы восстановили базу, в которой уже есть администратор, войдите под существующим аккаунтом.

### 3. Создать аккаунты и связать их

1. Откройте `https://ВАШ_ПУБЛИЧНЫЙ_IP/` в браузере и войдите под `root`.
2. В разделе **Аккаунты → Новый аккаунт** заполните логин, отображаемое имя и пароль. Создайте один аккаунт с ролью **Владелец дневника**, второй — с ролью **Партнёр**.
3. Откройте **Пары → Связать аккаунты**, выберите оба аккаунта и нажмите **Связать аккаунты**. Партнёр увидит календарь владельца после входа под своим логином.

Вместо ручной выдачи пароля администратор может создать **Ссылку для создания аккаунта** в разделе **Аккаунты**. Получатель сам задаст свой пароль. Такая ссылка создаёт аккаунт выбранной роли без пары. Для регистрации и привязки одним приглашением владелец дневника использует **Пригласить партнёра** в своём профиле. [Как работают приглашения](docs/INVITES_CONTRACT.md)

## Обновление и резервные копии

SQLite и ключ JWT лежат в именованном Docker-томе `open-source-flo_flo-data`. Перед обновлением сохраните согласованную копию `flo.db` и `jwt.key`. Обычное обновление использует прежний том. Для пересборки контейнеров выполните из папки сервера команды ниже. [Резервное копирование и обновление](docs/DEPLOYMENT.md#4-данные-обновление-и-android)

```bash
sudo git pull --ff-only origin main
sudo docker compose -p open-source-flo --env-file .env.ip-tls -f compose.prod.yaml up -d --build
```

Команда `docker compose down -v` удаляет тома, включая данные и сертификаты.

## Установка клиентов

- **iPhone.** Откройте HTTPS-адрес сервера в Safari, выберите **Поделиться → На экран «Домой»** и включите **Открыть как веб-приложение**, если переключатель доступен.
- **Android.** Соберите APK с адресом своего API. На компьютере потребуются JDK 17 и Android SDK. [Подготовка Android SDK и сборка](apps/android/README.md#сборка-на-macos)

```bash
./scripts/android.sh '-PAPI_BASE_URL=https://ВАШ_ПУБЛИЧНЫЙ_IP' assembleDebug
```

APK появится в `apps/android/app/build/outputs/apk/debug/app-debug.apk`.

## Локальная разработка

Установите Rust и Node.js с npm. Из корня репозитория создайте локального администратора и запустите API и веб.

```bash
./scripts/create-admin.sh
./scripts/dev.sh
```

Веб откроется на [127.0.0.1:5173](http://127.0.0.1:5173/). API слушает `127.0.0.1:8080`. Для проверки запуска PWA без сети используйте собранный веб через `npm --prefix apps/web run build` и `npm --prefix apps/web run preview`. Для входа в предпросмотр добавьте его адрес в `TRUSTED_ORIGINS` API.

`apps/web/` содержит веб и PWA, `apps/android/` — нативный клиент, `crates/api/` — API и миграции. Дополнительно доступны [контракт API](docs/AUTH_CONTRACT.md), [права доступа к дневнику](docs/CALENDAR_CONTRACT.md#права-и-приватность) и [инструкции по веб-разработке](AGENTS.md).
