# Веб-каркас

Одна Svelte-страница получает демонстрационный текст через `GET /api/message`. Адрес в браузере — `http://127.0.0.1:5173`. Ошибка сервера отображается на странице; кнопка выполняет новый запрос без использования кеша.

## Запуск

Нужен Node.js, совместимый с `engines` в `package.json` (рекомендуется Node.js 24). Из этой директории:

```bash
npm ci
npm run dev
```

API должен работать на `http://127.0.0.1:8080`. Vite проксирует `/api` и `/health` к нему; CORS на API для этого сценария не нужен. Другой адрес можно задать переменной `API_PROXY_TARGET`:

```bash
API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev
```

## Проверка и сборка

```bash
npm run check
npm run build
npm run preview
```

Предпросмотр сборки доступен на `http://127.0.0.1:4173` и также проксирует API. Для постоянного размещения файлы `dist/` обслуживаются веб-сервером с прокси `/api` на Rust-сервис. Vite dev/preview не предназначены для публичного production-размещения.

## Текущий объём

Реализованы состояния загрузки, успеха, ошибки и повторного запроса; таймаут — 10 секунд. Данные проверяются по формату `{ message: string, source: "sqlite" }`. Отображаемый текст поступает из API и не подменяется локальным примером.

Добавлены viewport/safe-area настройки и manifest с `display: standalone`. Service worker и автономная загрузка не реализованы; API не кешируется. Проверка установленной PWA на iPhone не проводилась. В интерфейсе нет изображений, внешних шрифтов и CDN.

Исходные технические источники: [Svelte](https://svelte.dev/docs/svelte/overview), [Vite server options](https://vite.dev/config/server-options).

## Проверки зависимостей

При первичной сборке `npm run check` прошёл без ошибок и предупреждений, `npm run build` завершился успешно. `npm audit` сообщил две записи уровня low, относящиеся к одной транзитивной зависимости `deepmerge` через `@sveltejs/vite-plugin-svelte`: [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Готовое исправление npm не предложил. Зависимость используется инструментом сборки и не входит в клиентский JavaScript; конфигурацию сборки следует брать из доверенного репозитория. Повторная проверка нужна после обновления зависимостей.
