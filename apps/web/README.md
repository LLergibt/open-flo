# Веб-приложение

Svelte-интерфейс входа, управления аккаунтами, приглашений и связывания людей в пары. Вход выполняется через API своего сервера. Самостоятельная регистрация партнёра доступна только по действительному одноразовому приглашению; открытой регистрации нет. Дневник и расчёты цикла пока не реализованы.

## Запуск

Из корня репозитория запустите `./scripts/dev.sh`, затем откройте `http://127.0.0.1:5173`. Скрипт запускает API и Vite с настройками локальной HTTP-разработки.

Первого администратора создайте в другом терминале из корня того же проекта:

```bash
./scripts/create-admin.sh
```

По умолчанию создаются логин и отображаемое имя root. Пароль выбирается пользователем и вводится скрыто в терминале. Публичного API для создания первого администратора нет. Страница `Настройка сервера` показывает эту команду, когда `/api/setup/status` возвращает `needs_setup: true`.

Для отдельного запуска веба из этой директории:

```bash
npm ci
npm run dev
```

Рекомендуется Node.js 24 или новее. Для `npm test` нужен Node.js со встроенной поддержкой удаления TypeScript-типов; проверено на Node.js 26. Зависимости приложения указаны в `package.json` и зафиксированы в `package-lock.json`.

API по умолчанию работает на `http://127.0.0.1:8080`. Vite проксирует `/api` и `/health`, браузер обращается к своему origin. Другой адрес API задаётся `API_PROXY_TARGET`:

```bash
API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev
```

При отдельном запуске API для локальной HTTP-разработки нужны `COOKIE_SECURE=false` и точный адрес веба в `TRUSTED_ORIGINS`, например `http://127.0.0.1:5173`. Для публичной установки с паролями используются HTTPS, Secure cookies и фактический HTTPS origin без wildcard.

## Возможности текущего этапа

- Вход, восстановление сессии после обновления страницы и выход.
- Профиль с именем, логином и ролью.
- Только для администратора: создание аккаунтов, список, включение/отключение и смена паролей.
- Только для администратора: выбор свободных активных владельца дневника и партнёра, создание пары, список и разрыв связи.
- Для владельца дневника и партнёра: своя пара, сведения о связанном аккаунте и прекращение связи с подтверждением.
- Для владельца дневника без пары: создание, копирование и отзыв одноразовой ссылки партнёра.
- Приглашение: просмотр имени владельца, регистрация нового партнёра либо вход в существующий аккаунт и отдельное подтверждение принятия.
- Для всех ролей: смена собственного пароля с текущим паролем и подтверждением нового. После успеха все сессии отозваны, показан вход.
- Загрузка, ошибки и повторные запросы; повторная отправка формы во время запроса блокируется.

Ни демонстрационные симптомы, ни медицинские прогнозы не подставляются. Интерфейс сохраняет персиковую/чернильную палитру, оконные рамки и типографику предыдущего экрана. Изображений, внешних шрифтов и CDN нет.

## Сессии

Код запросов находится в `src/lib/api.ts`, модели — в `src/lib/types.ts`. Браузер отправляет HttpOnly cookies через `credentials: same-origin`. Поля токенов из JSON входа игнорируются; `localStorage` и `sessionStorage` для авторизации не используются. Пароли не сохраняются приложением и очищаются из полей при отправке формы. Поведение собственного менеджера паролей браузера задаётся пользователем отдельно.

Защищённый запрос после HTTP 401 с кодом unauthorized выполняет одну попытку refresh и один повтор исходного запроса. Одновременные запросы разделяют одну выполняющуюся операцию refresh. HTTP 403 не запускает refresh. Если после refresh снова пришёл 401, интерфейс возвращается ко входу. Выход ожидает уже начатый refresh, предотвращает его позднее восстановление сессии и очищает отображаемый аккаунт. При сетевой ошибке выхода показано предупреждение и кнопка повторного завершения серверной сессии.

Неверный текущий пароль (401 invalid_credentials) не запускает refresh и не завершает сессию.

Проверка прав выполняется сервером; скрытие административной панели в UI само по себе не является защитой. Отзыв связи прекращает последующее получение данных, но не удаляет сохранённые вне приложения копии.

## Проверки и сборка

```bash
npm run check
npm test
npm run build
npm run preview
```

`npm test` выполняет 16 независимых от DOM тестов: cookie-режим и нормализация входа, single-flight refresh, ограничение повторов 401, отсутствие refresh на 403 и неверный текущий пароль, гонка logout/refresh, проверка ответов, POST-передача приглашения, фиксированная роль регистрации, очистка fragment и безопасное формирование ссылки. Используются только синтетические значения, без реальных аккаунтов.

Предпросмотр сборки работает на `http://127.0.0.1:4173`; этот origin также необходимо разрешить в API, если на нём проверяется вход. Для постоянного размещения файлы `dist/` обслуживаются веб-сервером с прокси `/api` на Rust API. Vite dev/preview не предназначены для production-размещения.

При текущей проверке `npm run check` завершился без ошибок и предупреждений, 16 тестов клиента API и ссылок прошли, `npm run build` завершился успешно. Полный сценарий с настоящим API и браузером проверяет координатор отдельно; эти тесты не доказывают корректность серверной авторизации.

## Приглашения

API возвращает ссылку на явно настроенный PUBLIC_APP_URL; если поле url равно null, веб собирает ссылку из текущего origin. Секрет находится в fragment /#invite=..., не в query. При открытии приложения fragment удаляется из адреса до запроса preview. Токен хранится только в памяти и сохраняется при входе/выходе внутри этого SPA до принятия или отмены. После обновления страницы приглашение нужно открыть заново по исходной ссылке.

Preview отправляет токен в POST JSON, не создаёт пару и не расходует приглашение. Вход тоже не создаёт пару: нужен отдельный выбор «Подтвердить приглашение». Регистрация всегда создаёт роль partner, связывает её по действительному приглашению и затем выполняет обычный вход с введённым паролем. Если регистрация прошла, а вход завершился ошибкой, интерфейс сообщает об уже созданном аккаунте и предлагает войти; повторная регистрация не выполняется автоматически.

Скопированная ссылка не сохраняется приложением. Кнопка отзыва прекращает действие неиспользованных приглашений, новая ссылка заменяет старую. Для копирования используется Clipboard API, при его недоступности выделяется поле для ручного копирования. Контракт — docs/INVITES_CONTRACT.md в корне проекта.

## PWA и зависимости

Добавлены safe-area настройки и manifest с `display: standalone`. Service worker и автономная загрузка не реализованы; ответы API не кешируются. Проверка установленной PWA на iPhone на этом этапе не проводилась.

При первичной сборке предыдущего этапа `npm audit` сообщил две записи low об одной транзитивной build-time зависимости `deepmerge` через `@sveltejs/vite-plugin-svelte`: [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4). Исправление тогда отсутствовало. В текущем этапе зависимости не изменялись; повторная проверка нужна при их обновлении.

Технические источники: [Svelte](https://svelte.dev/docs/svelte/overview), [Vite server options](https://vite.dev/config/server-options). Общий контракт API — `docs/AUTH_CONTRACT.md` в корне проекта.
